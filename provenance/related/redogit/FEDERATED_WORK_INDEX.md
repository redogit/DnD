# Federated Work Index

**Status:** active navigation layer — not a central authority  
**Predecessor:** [`BODY_OF_WORK.md`](BODY_OF_WORK.md), preserved as the first broad recovery snapshot

This index exists to make years of work easier to **find, separate, combine, test, play with, leave alone, revisit, or discard**.

It is deliberately *not* a master theory and not a command center.

> **The person remains the chooser. Tools, theories, institutions, projects, and AI can expand the possibility space; they do not own the choice.**

## No-center rule

```text
INDEX != AUTHORITY
RELATION != MERGE
RELATED != SAME
CONNECTION != EVIDENCE_TRANSFER
COORDINATION != HOMOGENIZATION
NAVIGATION != GOVERNANCE
ASSISTANCE != OWNERSHIP
MODEL != PERSON
PROJECT != PERSON
```

Each project keeps its own:

- purpose;
- evidence;
- chronology;
- source artifacts;
- failures;
- unresolved questions;
- terminology;
- authority boundary;
- right to remain separate.

The index may point between projects. It may not silently rewrite one project in the language of another.

## Human control

The desired relationship is:

`person → explores possibilities → chooses locally → acts → observes → changes mind if useful`

not:

`central system → chooses global interpretation → forces everything underneath it`.

Fun, curiosity, play, experimentation, wandering, and changing direction are legitimate parts of the work. Optimization is optional. Completion is not the only value.

## Shared pattern, not shared identity

One recurring structural observation remains useful:

> **higher organization = differentiation + relation + coordination**

That is a lens for asking questions, not a requirement that every branch become one theory.

The current outward exploration includes:

`cell → organism → animal/environment → social group → culture → tools → distributed human-machine work → institutions/civilization → meta-coordination → self-modeling systems`

The analogy is structural. It does not make a civilization an animal, a machine a person, or one project evidence for another.

# Typed bridges

When two branches touch, use an explicit relation rather than merging them.

Useful relation types include:

- `DIRECT_ANCESTRY`
- `METHOD_TRANSFER`
- `LATER_RESEARCH_BRANCH`
- `CONCEPTUAL_CONVERGENCE`
- `TECHNICAL_PREDECESSOR`
- `APPLICATION`
- `COUNTEREXAMPLE`
- `SUPPORTS_TEST_DESIGN`
- `PROVIDES_RECOVERY_PATTERN`
- `GENERATOR_ONLY`
- `HISTORY_ONLY`
- `PARALLEL_MATHEMATICAL_STRUCTURE`
- `OPEN_POSSIBLE_CONNECTION`

A relation should be removable without destroying either endpoint.

That is important: **connection is optional structure, not ownership.**

# Freedom to split things apart

Any combined structure should be decomposable again.

A useful integration should preserve:

```text
origin
chronology
independent identity
source artifacts
local terminology
local evidence status
local failure history
ability to detach
```

If integration destroys those, it is too centralized.

This also applies to AI assistance: a useful assistant should help expose choices, distinctions, evidence, and consequences—not make the user dependent on one global interpretation.

# Exploration lanes

A project can expose several equally legitimate entry modes.

## Play lane

Mess with it. Combine weird things. Generate worlds. Make music. Mutate operators. Explore visual or linguistic patterns. Follow curiosity.

No requirement that play justify itself as research.

## Build lane

Make something usable. Optimize locally. Test it. Repair it. Ship it when appropriate.

## Research lane

Freeze the question, controls, claim ceiling, evidence, counterprobes, and unresolved remainder.

## History lane

Recover old work without pretending reconstruction is the original source.

## Philosophy lane

Ask what matters, why the question is worth asking, and what kind of world the work should support.

The same artifact may be visible from several lanes without those lanes becoming interchangeable.

# Future rule

When another old idea, theory, theorem attempt, corollary, conversation, program, experiment, failure, poem, game, practical tool, or strange unfinished fragment is recovered:

1. give it its own identity first;
2. preserve its source and uncertainty;
3. classify what it actually established;
4. connect it only where the relation is useful;
5. make the connection removable;
6. do not require it to fit the current central story;
7. keep room to play with it again.

The objective is not one giant system.

The objective is **a living ecology of work that remains yours to navigate**.
